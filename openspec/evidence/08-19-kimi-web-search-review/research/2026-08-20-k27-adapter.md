# Research: K2.7 × Claude Science Web Search 最小根因与适配边界

- Query: K2.7 为什么在 Claude Science 完整 envelope 下只返回噪声头与幻影空搜索对，而同模型的最小 typed Web Search 请求能产生正确 query 和真实 results；如何在不删除 Science compute/tool context、不伪改 query、不增加静默 retry/fallback 的前提下，让 K3、K3-256k、K2.7 都兼容 Web Search。
- Scope: mixed（当前源码与已归档真实 provider/Science 证据；本研究未新增真实 provider 请求）
- Date: 2026-08-20

## Findings

### 结论

当前能证明的**最小根因边界**是：

```text
K2.7 + typed web_search + 最小 query-only envelope
  -> query 正确、18 results、id adoption 命中
  -> 但没有最终正文

K2.7 + typed web_search + Claude Science 完整 envelope
  -> typed 声明已保留、compute tail 已重排、dropped=0
  -> 只有 noise + 无键空结果幻影对
  -> 模型明确说 Web Search 不可用
```

这已经排除“CSSwitch 丢了 typed declaration”“K2.7 完全没有搜索能力”和“响应过滤器把真实结果
删掉”三种解释；**尚不能把根因归到任一单字段**。当前证据只支持
`K2.7 × Science envelope` 的组合缺陷，不能直接写成 system、24 个 client tools、thinking、
compute tail 或 transport header 中某一个字段导致。

推荐执行顺序：

1. 先按本文实验矩阵对一份**仅含本次测试消息的 Science-like 请求**做成对、单变量 A/B。
2. 只有当一个可丢弃/可规范化的非语义字段稳定造成 `real search -> phantom` 翻转时，才做
   K2.7 request normalization。
3. 若触发因子是必须保留的 system/tool/history/compute 语义，或没有单一安全边界，停止继续删字段，
   启用 **K2.7-only query-only adapter**：主模型决定是否搜索与 query，专用 nested 请求执行搜索，
   第二次主模型调用生成最终正文。
4. K3 已证实完整 Science 原生路径有效，不应统一切到多调用 adapter；K3-256k 先跑同样的原生
   Science 验收，只有复现同一失败才加入 adapter allowlist。

这是比恢复整个旧实现更窄的决策：**复用旧 bridge 的已验证语义，不原样恢复 920 行实现**；复用
当前 transport、SSE validator/collector 和 Kimi search filter，不再写第二套 HTTP/auth/SSE parser。

### 当前请求真实会经过哪些改写

当前所有 Kimi 模型共用 `kimi-anthropic-relay`，contract 本身没有 K2.7/K3 的 Web Search 策略差异：

- contract 绑定 `kimi` / `kimi-coding` 两个 template，transport 为 `anthropic_messages`，thinking policy
  为 `upstream_default`，总超时 180s、read-idle 300s：
  `catalog/provider-contracts.v1.json:41-75`。
- 默认三个目标模型分别是 `k3-256k`、`k3`、`kimi-for-coding`：
  `desktop/gateway/src/profile.rs:118-125`；Science canonical role 最终解析为相同 upstream id：
  `desktop/gateway/src/static_profile.rs:552-568`。
- `RelayFlavor` 只看 contract id；`kimi-anthropic-relay` 下所有模型都得到 `Kimi` flavor：
  `desktop/gateway/src/anthropic_compat.rs:44-55`。

请求路径如下：

```text
Science JSON + inbound transport metadata
  -> model selector 解析为 upstream model
  -> transform_relay_request_for_contract
       model := resolved target
       Kimi: compute tail reorder
       Kimi: document placeholder
       Kimi: old Web Search history pairing repair
       client tool input_schema normalization
       thinking auto/adaptive -> omitted
       typed web_search preserve; unsupported server tools drop
  -> messages::{open_stream | post_nonstream}
       复用 inbound anthropic-version / beta / x-app / user-agent / ?beta=true
       contract Bearer auth
  -> Kimi
  -> SearchNoiseFilter / strip_nonstream_noise
  -> SSE validator
  -> Science
```

代码证据：

- transform 的固定顺序见 `desktop/gateway/src/anthropic_compat.rs:864-910`。
- compute tail 只交换末尾两条完整 user message，不删除正文：
  `desktop/gateway/src/anthropic_compat.rs:387-411`。
- typed Web Search 被识别并保留：`desktop/gateway/src/anthropic_compat.rs:288-329,455-487`。
- client tools 只归一 `input_schema`，其它字段沿用 clone：
  `desktop/gateway/src/anthropic_compat.rs:490-539`。
- `max_tokens`、`temperature`、`metadata`、普通 system blocks 不在 transform 中被删除；它们仍到达上游。
- inbound `?beta=true` 与四个允许的 transport headers 由
  `desktop/gateway/src/messages.rs:90-140,217-261,322-366` 透传/归并；nested adapter 不应另写 auth
  或 header 构造。

因此 K2.7/K3 当前唯一的模型级变量是最终 `target_model`；其余请求补偿完全相同。若实现 K2.7 专属
适配，分流必须发生在 selector 已解析之后、普通 Kimi stream/nonstream 转发之前，即
`desktop/gateway/src/server.rs:986-1045` 这一边界。

### Claude Science envelope 的已知结构与证据边界

归档的真实 Science 捕获确认：

- 每轮都带 1 个 `web_search_20250305` server tool 和 24 个 client tools，工具清单含 compute、文件、
  环境、网络授权等能力：
  `.trellis/tasks/archive/2026-08/08-06-kimi-for-coding-channel/research/science-raw-capture-2026-08-06.md:35-49`。
- 原始 thinking 为 `{"type":"auto"}`；当前 transform 会删除它，让 Kimi 使用 upstream default：
  同文件 `:54-59`，当前实现 `anthropic_compat.rs:155-186,884-900`。
- system 是带 cache_control 的 text block array；tools 也带 cache_control；另有 temperature、metadata、
  billing header：同文件 `:66-76`。
- 历史 query-only 请求 5/5 触发真实搜索；Science-like 的两阶段模拟中，主模型先生成 ordinary
  query tool，再用单条 query + typed tool 搜索成功：同文件 `:106-142`。
- 2026-08-06 的旧探针曾证明 max_tokens、轮次、是否带 system、是否同时有 client tools、max_uses、
  tool_choice:auto 都不是当时“声明未搜索 -> 429”的原因：
  `.trellis/tasks/archive/2026-08/08-06-kimi-for-coding-channel/research/upstream-probe-2026-08-06.md:50-77`。
  这只能降低这些变量的优先级，**不能直接证明它们与 2026-08-20 的 phantom/no-final-text 现象无关**。

当前没有保存一份可直接重放的、完整而脱敏的 2026-08-20 Science body；只有结构摘要、规则日志和
UI 结果。因此下面矩阵必须使用本次新建测试会话的请求形状，不能从私人历史或真实日志补齐正文。

### 可独立 A/B 的变量

每个实验都需要同时记录四个独立结果，不能只看 HTTP 200：

```text
planner: 是否出现 name=web_search 的真实 server_tool_use，query 是否语义正确
executor: result content 是否为真实数组、结果数、是否配对
answer: 是否有非噪声最终 text，stop_reason 是否合理
downstream: Science card / reload / 下一轮 history 是否成立
```

所有 A/B 必须在同一模型、同一时段、同一安全 prompt 下成对执行；若最小基线当时也失败，就只记录
“远端时段不可判”，不能把候选字段写成根因。

| 优先级 | 固定项 | A | B | 能回答什么 |
| --- | --- | --- | --- | --- |
| P0 | K2.7、相同 transport、相同安全 query | 当前已知最小 query-only body | 当前 transformed Science-like body | 重建 planner-success / phantom 基线；两者必须邻近执行 |
| P1 | 完整 system/tools/top-level 保持 | 只留重排后的最新真实 user intent | 完整 messages/history + compute tail | 干扰是否来自 message/history，而不是 tools/system |
| P1 | 完整 system/messages/top-level 保持 | tools 仅 typed Web Search | typed Web Search + 24 client tools | 24-tool envelope 是否为充分干扰因素 |
| P1 | 完整 tools/messages/top-level 保持 | 无 system | 完整 Science system block array | system 整体是否为充分干扰因素 |
| P1 | body 固定 | Science inbound path/header/query | 合成最小 transport metadata | body 与 transport 身份分层；特别核对 `?beta=true`、UA、x-app、anthropic-beta |
| P2 | full tools 已证明触发时 | 24 client tools 二分保留 | 另一半 | 用 ddmin 找最小 tool subset；不能一开始逐个工具烧请求 |
| P2 | 最小 tool subset 固定 | 保留 tool name + 简化 schema/description | 完整 schema/description/cache_control | 区分“工具存在”与“描述/schema 内容影响 planner” |
| P2 | full messages 已证明触发时 | 最新 user + compute context | 再逐步加入 assistant/tool history | 找出 latest content 还是历史工具块导致 |
| P2 | 两条 user 固定 | string content | 单 text-block array | content 形态是否影响 K2.7 planner |
| P2 | 两条 user 文本固定 | `[compute, intent]` | `[intent, compute]` | 复核 K2.7 是否与 K3 同样受最后 user 影响；不能据 K3 结果外推 |
| P2 | system 已证明触发时 | billing header / 基础 system | 其它 cache-controlled system blocks 逐组加入 | 定位 system 语义还是 cache wrapper |
| P3 | body 其它字段固定 | thinking omitted | `disabled` / `enabled` 各一组 | 当前 production 已 omitted；只用于排除 K2.7 planner/answer 对 thinking 的模型差异 |
| P3 | body 其它字段固定 | tool_choice absent | `{type:auto}` | 排除显式 auto；forced `tool` 不属于正常搜索主轮，不能混入 |
| P3 | body 其它字段固定 | Science max_tokens | 32000 / 较小已知可用值 | 历史只排除了旧 429，不排除 no-final-text；同时观察 truncation/usage |
| P3 | body 其它字段固定 | 无 temperature/metadata/output_config | 逐项恢复 | 顶层非语义字段的最后排查 |
| P3 | 已定位 body | stream=true | stream=false | 验证 response contract；不能用 nonstream 成功代替 Science stream 成功 |

优先先做三组“大块替换”而不是几十个字段逐个试：messages-only、tools-only、system-only。只有某组能
稳定翻转，才在组内二分；这是 provider 请求数最少、且不会先入为主猜某个字段的办法。

### Request normalization 的允许条件与停止条件

只有同时满足以下条件，才可安全做 request normalization：

1. 同时段 query-only control 能产生语义正确的真实 pair；full Science control 稳定产生 phantom。
2. 一个字段或最小组合连续至少 3 组 A/B 都可逆地翻转结果：加回必失败、去除必恢复。
3. 该字段是非语义 envelope（例如冗余 cache wrapper、无效 transport marker），或可在不丢信息的情况下
   规范化；不能是 system 指令、client tool、compute context、用户历史、tool_result。
4. 判据能绑定 `kimi-anthropic-relay + 精确已验证 model id + 精确 Science shape`，并只在产生净改写时记 rule。
5. K3 与 K3-256k 负控制、K2.7 普通工具轮、nonstream、后续 history 全部通过。

出现以下任一情况，应停止继续删字段，转 query-only adapter：

- 只有删除 full system、24 client tools、compute snapshot 或历史才能恢复；这些都是 Science 的真实功能输入。
- 根因是两个以上语义字段的交互，无法形成稳定、窄、可解释的签名。
- 最小 query-only 请求能搜索但仍稳定没有最终 text；这说明即使修好 planner，K2.7 inline
  `search -> answer` 仍未完成。
- 同一 A/B 在 paired control 健康时仍随机翻转，不能与远端负载/模型选择区分。
- 候选修复依赖追加“请忽略这些上下文”提示、从最后 user 猜 query、响应回来后改 query、失败后 command
  fallback 或静默 retry；这些都不满足可验证合同。

#### 已研究的三阶段设计

归档设计的不可省略闭环是：

```text
main #1（完整 Science 语义）
  typed server declaration -> Gateway 私有 ordinary query tool
  -> 不搜索：直接返回正常 main #1
  -> 搜索：得到 model-chosen query + exact main tool_use id

nested search（固定 query-only）
  同 endpoint/model/auth
  messages = 单条 query user text
  tools = 仅 typed web_search_20250305
  thinking absent, stream=true
  -> 真实 server_tool_use + web_search_tool_result

main #2（回答合成）
  main #1 assistant thinking/tool_use
  + exact-id user tool_result（来自真实 nested result）
  + 保留 Science 其它 client tools，移除私有 search tool 防递归
  -> 最终正文/普通 Science tool call
```

证据与边界在
`.trellis/tasks/archive/2026-08/08-03-kimi-web-search-compat/research/science-kimi-nested-websearch-adapter.md:15-30,41-72,74-128`。

这三阶段不能压成“每个带 declaration 的请求直接 search-only”：typed tool 是能力声明，不代表每轮都
需要搜索；直接拿完整 prompt 当 query 会泄露不必要上下文、误搜多意图问题，并丢普通工具与最终 synthesis：
同文件 `:108-119`。

#### 当前代码能最小复用什么

可直接复用：

- `messages::{open_stream, post_nonstream}`：同一 endpoint/auth/header/error mapping；
  `desktop/gateway/src/messages.rs:606-647,682-715`。
- `anthropic_sse::Validator`：验证唯一 message lifecycle、连续 index、terminal error，并把
  `message_stop` 留到 clean EOF：`desktop/gateway/src/anthropic_sse.rs:31-103,153-230`。
- `AnthropicStreamMessageCollector`：已经能从 SSE 重建 text/thinking/signature/tool input/citations，
  server result 整块可从 start 保留：`desktop/gateway/src/server.rs:368-606`。它当前没有 production caller，
  应抽成 adapter 可用 helper，而不是另写 parser。
- `SearchNoiseFilter`：nested response 先按当前合同剥噪声、严格识别 phantom、采纳 pair id，再交 validator/
  collector。它负责响应规范化，不负责多调用 orchestration：
  `desktop/gateway/src/kimi_search_noise.rs:243-318,613-695`。
- `repair_web_search_result_pairing`：对 Science 下一轮回放的旧/瘦身历史继续生效；本任务同时收窄到
  `name=web_search` 与 exact `content: []` 后，query-only adapter 不应另写历史修复器。

不能复用或不能假装一行解决：

- `SearchNoiseFilter` 是一条单响应流的块过滤器，不会执行 main #1/nested/main #2，也不会聚合 usage。
- 当前 `handle_stream()` 在上游 2xx 后立刻向 Science 写 HTTP/SSE lifecycle：
  `desktop/gateway/src/server.rs:840-873`。adapter 必须先缓冲 main #1 与 nested；否则一旦向 Science 发出
  第一个 lifecycle，就无法隐藏内部 query tool 并再拼 main #2。
- 当前 collector 上限 64 MiB 是历史 continuity 上限，不应直接作为 nested search result 配额；adapter
  需较小的有界结果上限，但不要新造配置开关。
- 不能复用模型 endpoint 的普通 GET retry：inference 的 main/nested 错误都必须一次失败即显式返回，
  不把 429/5xx解释成“换路径再试”。

### 最小 query-only adapter 推荐

若实验达到 adapter 停止条件，推荐新增一个 contract/model-scoped 模块，而不是把三阶段状态塞进
`server.rs`：

```text
trigger = provider_contract == "kimi-anthropic-relay"
       && resolved target_model in VERIFIED_QUERY_ONLY_MODELS
       && request contains typed web_search_*
```

首个 allowlist 只应包含真实失败并通过 adapter live 验收的 `kimi-for-coding`。`k3` 保持 native；
`k3-256k` 先验证 native。`kimi-for-coding-highspeed`、开放平台 `kimi-k2.7-code` 不是本目标的自动别名，
没有对应端点/模型 live 证据前不能顺带启用。

最小实现合同：

1. 保留完整 Science system/messages/compute/client tools；只把 typed Web Search capability 映射为一个
   reserved ordinary `{query:string}` tool。reserved name 冲突、forced choice、空/过长 query 明确 400/502。
2. main #1 完整缓冲。未调用 reserved tool：返回 main #1；调用一个 reserved tool：进入 nested；与普通
   client tool 并发、重复/多个 search call 首版明确失败，不执行半套结果。
3. nested builder 固定 query-only shape，继续使用同 `GatewayConfig`、resolved model 和当前
   `AnthropicTransport`；不得读取配置/key，也不得另写 HTTP。若 transport A/B 证明 K2.7 nested 必须固定
   CLI 身份，再把这一点作为单独、可测试的 contract 字段，不在 adapter 里硬编码猜测。
4. nested 必须得到 `server_tool_use(name=web_search)` + 对应 `web_search_tool_result`。真实带键零结果可保留；
   缺失/字符串/对象 content 不得当 phantom 删除；未知/畸形 lifecycle 返回 502。
5. main #2 使用 main #1 的 exact tool id 回灌真实 nested result，移除 reserved tool 防递归，保留其它
   Science tools。nested 没有最终正文也没关系，main #2 必须负责生成正文。
6. 对 Science 只输出一个合法 response lifecycle，并由真实 nested blocks 生成原生 Search card；不能
   暴露 reserved ordinary tool。下一轮以 Science 实际回放为准，经现有 pairing repair 后必须通过。
7. adapter 无自动 retry/fallback；main #1、nested、main #2 任一 4xx/429/5xx/协议错误如实失败。共享一个
   总 deadline，不得让三次调用各吃满 180/300 秒。
8. usage 对三次真实调用 checked-add 后写入最终 usage；只报告 main #2 会静默少算。日志只记 model、stage、
   status、calls、rule id、usage 数值，不记 query、结果或正文。

首版“最多一个 reserved search call，混合并行 fail closed”是明确的 ponytail 上限；当真实 Science
证明同一轮需要多个内部 query，且单次 query 造成可见功能缺口时，再升级为有界多查询执行器。不要为
归档中一次 `tool_use×2` 的旧模拟先恢复全部并行 orchestration。

### 是否给三个模型统一 adapter

| 维度 | 所有模型统一 query-only adapter | 仅失败模型启用 | 判定 |
| --- | --- | --- | --- |
| 功能证据 | K3 已有一调用 native Science 7 轮成功；统一会替换已工作的路径 | K2.7 已确认 full Science 失败；按 model 修真正中缺口 | **仅失败模型** |
| 首字节延迟 | Science 每轮都有 typed declaration，所有轮都要先完整缓冲 main #1 | 只有 K2.7 承担；K3/K3-256k native 可直接 streaming | **仅失败模型** |
| usage | 搜索轮最多三次调用；统一后 K3 也多付 main/nested/main | 额外 usage 只落在必须隔离 planner/executor 的模型 | **仅失败模型** |
| failure contract | 所有模型都新增 nested deadline/429/collector/usage 失败面 | K3 继续已有单调用错误合同；K2.7 adapter 显式失败 | **仅失败模型** |
| Science 原生卡片 | 两者都可由真实 nested blocks生成，但统一方案无额外 UI 收益 | K3 保持已实测 native card；K2.7 由 adapter补齐 | **仅失败模型** |
| 后续历史 | 统一把三模型都带进隐藏 main history/visible search history差异 | 只验证 K2.7 的新历史边界，K3 保持已通过的 adoption/repair | **仅失败模型** |
| 维护 | 一个行为看似统一，但 contract 内部实际模型能力不同，问题更难定位 | 一个 exact allowlist + 同一 adapter 实现；新增模型需 live 证据 | **仅失败模型** |

K3-256k 当前不能用“K3 同族”直接判通过，也不能因未测就提前走 adapter。正确顺序是先跑 native
Science 搜索/追问/重载：通过则保持 native；若复现与 K2.7 相同的 planner/no-text 失败，再用同一 adapter
实现、扩充 exact model allowlist，不复制一套模块。

### 实验与实现的停止门

#### A/B 根因实验停止

- **成功定位 normalization**：同一最小字段/组合 3/3 可逆翻转，且不删除语义输入；进入窄 request patch。
- **进入 adapter**：大组结果指向必须保留的 system/tools/history，或 query-only 仍无正文，或没有稳定
  单字段；停止继续试探式删字段。
- **时段不可判**：paired minimal control 也无真实 pair/返回 429/5xx；停止，不把负载写成字段根因。

#### Adapter 验收停止

必须同时成立才算 K2.7 adapter 完成：

- 全新 Science 会话 query、result、card、最终正文语义正确；不是 HTTP 200 或“有结果块”就算成功。
- 同会话无搜索追问、再次搜索、普通 client tool、计算轮都正常。
- 整页重载后 card/query/result 保留；下一轮无 pairing repair 依赖、无 400。
- direct stream 与 nonstream 均明确：若 adapter 首版只支持 Science stream，nonstream 必须显式拒绝，
  不能静默走坏的 native K2.7；若声称支持则必须真实验收。
- K3 与 K3-256k 原生负控制不回归。

### 最小测试集合及其真实回归目标

1. `anthropic_compat` unit：exact K2.7 trigger、K3/K3-256k/兄弟 provider 负控制；能抓 adapter 越界。
2. adapter unit：typed declaration -> reserved tool；query/id 校验；no-search 一调用、search 三调用；能抓声明
   被误当本轮必须搜索、reserved tool 泄漏、ID 错配。
3. adapter local-upstream integration：依次返回 main #1 tool_use、nested real search pair、main #2 text；
   断言下游仅一个 lifecycle、native search pair + 最终 text、usage checked-add；能抓旧 bridge 的 start-only
   payload、双 message lifecycle 和少算 usage。
4. error matrix：nested 429/5xx、partial SSE、缺失 result、非 Web Search server tool、content 缺失/string/object、
   deadline；断言显式 4xx/5xx/502/504，不生成假正文、不重试。
5. history round-trip：对下游响应做规范客户端重建，再作为下一轮 Science history 送入；能抓 card 落盘后
   server use 消失/ID 不配导致的后续 400。
6. `bash test/run_all.sh` 三层门禁；现有 `test/run_loopback.sh` 当前只测控制服务，不含 provider inference
   (`test/run_loopback.sh:1-80`)，若验收要求“真实进程 + fake upstream”，需增加一个隔离 loopback case，
   不能把 Rust unit mock 写成现有 loopback 已覆盖。
7. 真机：K3、K3-256k、K2.7 各自 `搜索 -> 不搜索追问 -> 再搜索 -> 重载`；K3 与至少一个其它模型
   跑 nonstream。证据必须分栏，见 `.agents/rules/testing-and-evidence.md:1-12`。
