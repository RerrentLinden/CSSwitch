# WebUI Quality Guidelines

## 场景：修改控制台

### 1. 范围 / 触发条件

改动 `desktop/gateway/ui/index.html` 时适用。它是唯一的前端文件。

### 2. 合同

- **保持单文件、零依赖**：不引入框架、构建步骤或外部 CDN。控制台跑在 loopback，
  引外部资源既拖慢启动也制造离线故障。
- **图标也在这一个文件里**:页眉标题旁是一份内联 SVG;页签图标由脚本把**这同一份**序列化成
  `data:image/svg+xml` 设到 `<link rel="icon">` 上,在读状态之前就设好(服务连不上、或退出后
  页眉被换掉,页签图标都还在)。不引图片文件、不加第二份拷贝、不另开一个返回图标的路由。
  图形来自 `packaging/icon/console-glyph.svg`(`gen.py` 生成,与应用图标的简化稿同一组参数),
  改图后把新内容同步进来。图标自带深色底板,深色主题下靠 `var(--line)` 的一圈细线与背景分开。
- **版本号取自状态接口**(`state.version`),不写死在页面里:页面与服务编在同一个二进制中,
  显示的就是后台实际在跑的版本。更早的服务不报告版本号,那时留空,不显示 `undefined`。
- **文案对两种启动方式都成立**:同一个页面既被安装版使用,也被 `./csswitch` 使用。涉及
  「怎么再次启动」「日志在哪」的句子要把两种情况都说到,不能只写其中一种。
- **主题跟随系统**:颜色全部走 CSS 变量,`prefers-color-scheme` 下只重定义变量。
- **凭证只进不出**:API Key 输入框可以填,但服务端返回的状态里只有
  `has_api_key: true/false`。页面上任何地方都不得渲染 key 本身。
  留空提交表示"保持不变",不是"清空"——否则每次改模型槽都要重填 key。
- **危险操作要确认**:退出服务、以及会打断进行中会话的操作(切换模式、切换联网搜索总开关、
  切换运行中沙箱的渠道),必须先 `confirm()`。
  退出服务会先停掉 Science 与免登录沙箱,确认文案必须写明这一点和会话会被打断;
  退出后的卡片列出已停止的实例,停止失败的原文逐条展示。
  操作被服务端以"有会话正在进行"拒绝时,把它转成确认框再带 `force` 重试,
  而不是直接报错了事;用户取消时界面回到操作前的状态(服务端此时什么都没改)。
  沙箱渠道的拒绝文案是"沙箱正在运行"(沙箱没有可靠的会话数,只要在运行就要确认),同样处理。
- **两组模式卡片,同一套渲染,各管各的实例**:正式实例的在「当前连接」卡片(选中态看
  `state.mode`),沙箱的在「免登录沙箱」卡片(看 `state.sandbox_mode`,只有 Kimi / DeepSeek)。
  两张卡片的说明文字各自写明它管的是哪个实例。沙箱没有官方 Claude(它是虚拟登录),
  不放一张置灰的卡片,原因写在说明文字里。
- **带重启的请求在途时,禁用触发它的控件**:切换运行中沙箱的渠道要停、起一次沙箱,好几秒。
  在途时两张沙箱渠道卡片禁用,周期轮询重绘卡片时保持禁用;中途再点会留下错配状态。
  完成后只调 `poll()` 刷状态,不调 `refresh()` —— 后者会重绘渠道配置表单。
- **失败要看得见**:控制面返回的错误原文直接展示,不吞掉、不替换成泛化文案。
- **改动即提交的开关,失败后以服务端为准**:请求失败不等于什么都没发生 —— 联网搜索总开关
  的"Science 重启失败"发生在存盘之后。失败时重新读一次状态给复选框赋值,读不到才退回操作前的
  勾选;不要无条件把勾选拨回去。请求进行中禁用复选框。
- **周期轮询只刷状态,不重绘配置表单,也不给开关赋值**:`setInterval` 那条刷新是给 Science
  运行状态用的。让它重跑表单渲染会把用户填到一半的地址、模型槽无声覆盖回已保存值,
  让它给开关赋值会把正在提交的开关弹回去 —— 用户看到的是"我明明改了却自己变回去了"。
  全量重绘只在首次加载与保存/切换之后做;开关在首次加载与自己的操作完成后赋值。
- **控件放在它的作用范围所在的位置**:只对一个渠道起作用的控件只在那个渠道的标签页渲染,
  别的标签页不该出现一个按了不起作用的开关;全局生效的控件(联网搜索总开关对三种模式与
  免登录沙箱都生效)放在全局卡片里,不要塞进某个渠道的表单,更不要每个渠道各放一个。
- **提示文案必须对每一层都成立**:地址与模型槽要重启 Science 才生效;联网搜索总开关的网关
  一侧下一次请求就生效,Science 一侧要重启,免登录沙箱要用户手动重启 —— 一句笼统的
  "已生效"或"重启后生效"至少对其中一层是假话。成功提示按服务端响应逐项拼
  (`science_restarted`、`sandbox_restart_required`),每一句只说已经成立的事。

### 3. 校验与错误矩阵

| 条件 | 要求行为 |
| --- | --- |
| 服务不可达 | 页面顶部插入明确的错误卡片,不是白屏 |
| 模型探测失败 | 展示上游原文,不显示空清单 |
| 保存配置成功 | 清空 key 输入框,提示写明生效时机(下次切换或重启 Science) |
| 切换联网搜索总开关成功 | 提示分别说明 Science、网关、免登录沙箱三层的生效情况 |
| 切换联网搜索总开关失败 | 展示原文,并按服务端当前状态给复选框赋值 |
| 切换沙箱渠道成功 | 按响应如实写:`sandbox_restarted` → 已切换并重启;否则 → 下次启动沙箱时生效 |
| 切换沙箱渠道失败 | 展示原文;选中态以服务端当前状态为准(重启失败发生在存盘之后) |
| 请求日志的「实例 · 渠道」列 | 显示 `正式 · kimi` / `沙箱 · deepseek`:两个实例各有各的模式,只写渠道分不清是哪一边 |
| 全局 `input` 是 `width:100%` | 复选框必须显式 `width:auto`,否则铺满整行 |
| 状态里没有 `version`(更早的服务) | 页眉版本留空 |

### 4. 可视化验收是必需项

样式与交互改动**必须在浏览器里真实打开确认**,截图为准。
`cargo test` 不覆盖任何一行 HTML/CSS/JS。

验收动线:打开控制台 → 页眉有图标、右侧版本号与 `--version` 一致、浏览器页签上有图标 →
三张模式卡片状态正确 → 联网搜索总开关在「当前连接」卡片、
渠道标签页里没有第二个 → 切换总开关(提示逐层成立、有会话时弹确认框、等一个轮询周期不弹回)→
渠道配置四槽渲染正确 → 获取可用模型 → 保存 → 刷新页面确认落盘 →
深色模式(页眉图标的底板仍与背景分得开)→ 切换模式 → 日志表格 → 退出服务
(退出后的卡片写明两种再次启动的方式)。

沙箱渠道选择器另走一遍:两张渠道卡片选中态正确 → 沙箱未运行时切换(只保存,正式实例的模式不变)→
沙箱运行中切换(弹确认;取消后界面与服务端都不变)→ 确认后的结果如实显示 → 向两个入口各发请求后
日志表格分别显示正式与沙箱 → 等一个轮询周期选中态不弹回。「沙箱运行中」用 loopback 同款的假沙箱
进程造出来(命令行同形 + 写进沙箱 lock 的 pid);服务进程的 PATH 最前面放一个什么都不做的假
`security`,否则确认后的启动流程会去调真实的那个。原生 `confirm()` 会卡住自动化浏览器:
把 `window.confirm` 换成「记下文案、返回预设答案」的桩来走两条分支,报告里写明弹窗外观未截图。

无头浏览器截图看不到页签栏:页签图标要么在真实浏览器里看,要么把脚本生成的那个 data URI
取出来单独渲染成 16 / 32 px 确认图形。

服务用隔离 HOME 起在临时端口验收,不碰用户真实的 `~/.csswitch`。
