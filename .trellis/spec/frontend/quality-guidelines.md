# WebUI Quality Guidelines

## 场景：修改控制台

### 1. 范围 / 触发条件

改动 `desktop/gateway/ui/index.html` 时适用。它是唯一的前端文件。

### 2. 合同

- **保持单文件、零依赖**：不引入框架、构建步骤或外部 CDN。控制台跑在 loopback，
  引外部资源既拖慢启动也制造离线故障。
- **主题跟随系统**:颜色全部走 CSS 变量,`prefers-color-scheme` 下只重定义变量。
- **凭证只进不出**:API Key 输入框可以填,但服务端返回的状态里只有
  `has_api_key: true/false`。页面上任何地方都不得渲染 key 本身。
  留空提交表示"保持不变",不是"清空"——否则每次改模型槽都要重填 key。
- **危险操作要确认**:退出服务、以及会打断进行中会话的模式切换,必须先 `confirm()`。
  切换被服务端以"有会话正在进行"拒绝时,把它转成确认框再带 `force` 重试,
  而不是直接报错了事。
- **失败要看得见**:控制面返回的错误原文直接展示,不吞掉、不替换成泛化文案。

### 3. 校验与错误矩阵

| 条件 | 要求行为 |
| --- | --- |
| 服务不可达 | 页面顶部插入明确的错误卡片,不是白屏 |
| 模型探测失败 | 展示上游原文,不显示空清单 |
| 保存配置成功 | 清空 key 输入框,提示"运行中链路不变" |

### 4. 可视化验收是必需项

样式与交互改动**必须在浏览器里真实打开确认**,截图为准。
`cargo test` 不覆盖任何一行 HTML/CSS/JS。

验收动线:打开控制台 → 三张模式卡片状态正确 → 渠道配置四槽渲染正确 →
获取可用模型 → 保存 → 切换模式 → 日志表格 → 退出服务。
