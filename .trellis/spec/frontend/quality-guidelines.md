# WebUI Quality Guidelines

## 场景：修改控制台

### 1. 范围 / 触发条件

改动 `desktop/gateway/ui/index.html` 时适用。它是唯一的前端文件。

### 2. 合同

- **保持单文件、零依赖**：不引入框架、构建步骤或外部 CDN。控制台跑在 loopback，
  引外部资源既拖慢启动也制造离线故障。
- **主题跟随系统**:颜色全部走 CSS 变量,`prefers-color-scheme` 下只重定义变量。
- **凭证只进不出**:API Key 输入框可以填,但服务端返回的状态里只有
  `has_api_key: true/false`。页面上任何地方都不得渲染 key 本身。
  留空提交表示"保持不变",不是"清空"——否则每次改模型槽都要重填 key。
- **危险操作要确认**:退出服务、以及会打断进行中会话的操作(切换模式、切换联网搜索总开关),
  必须先 `confirm()`。
  退出服务会先停掉 Science 与免登录沙箱,确认文案必须写明这一点和会话会被打断;
  退出后的卡片列出已停止的实例,停止失败的原文逐条展示。
  操作被服务端以"有会话正在进行"拒绝时,把它转成确认框再带 `force` 重试,
  而不是直接报错了事;用户取消时界面回到操作前的状态(服务端此时什么都没改)。
- **失败要看得见**:控制面返回的错误原文直接展示,不吞掉、不替换成泛化文案。
- **改动即提交的开关,失败后以服务端为准**:请求失败不等于什么都没发生 —— 联网搜索总开关
  的"Science 重启失败"发生在存盘之后。失败时重新读一次状态给复选框赋值,读不到才退回操作前的
  勾选;不要无条件把勾选拨回去。请求进行中禁用复选框。
- **周期轮询只刷状态,不重绘配置表单,也不给开关赋值**:`setInterval` 那条刷新是给 Science
  运行状态用的。让它重跑表单渲染会把用户填到一半的地址、模型槽无声覆盖回已保存值,
  让它给开关赋值会把正在提交的开关弹回去 —— 用户看到的是"我明明改了却自己变回去了"。
  全量重绘只在首次加载与保存/切换之后做;开关在首次加载与自己的操作完成后赋值。
- **控件放在它的作用范围所在的位置**:只对一个渠道起作用的控件只在那个渠道的标签页渲染,
  别的标签页不该出现一个按了不起作用的开关;全局生效的控件(联网搜索总开关对三种模式与
  免登录沙箱都生效)放在全局卡片里,不要塞进某个渠道的表单,更不要每个渠道各放一个。
- **提示文案必须对每一层都成立**:地址与模型槽要重启 Science 才生效;联网搜索总开关的网关
  一侧下一次请求就生效,Science 一侧要重启,免登录沙箱要用户手动重启 —— 一句笼统的
  "已生效"或"重启后生效"至少对其中一层是假话。成功提示按服务端响应逐项拼
  (`science_restarted`、`sandbox_restart_required`),每一句只说已经成立的事。

### 3. 校验与错误矩阵

| 条件 | 要求行为 |
| --- | --- |
| 服务不可达 | 页面顶部插入明确的错误卡片,不是白屏 |
| 模型探测失败 | 展示上游原文,不显示空清单 |
| 保存配置成功 | 清空 key 输入框,提示写明生效时机(下次切换或重启 Science) |
| 切换联网搜索总开关成功 | 提示分别说明 Science、网关、免登录沙箱三层的生效情况 |
| 切换联网搜索总开关失败 | 展示原文,并按服务端当前状态给复选框赋值 |
| 全局 `input` 是 `width:100%` | 复选框必须显式 `width:auto`,否则铺满整行 |

### 4. 可视化验收是必需项

样式与交互改动**必须在浏览器里真实打开确认**,截图为准。
`cargo test` 不覆盖任何一行 HTML/CSS/JS。

验收动线:打开控制台 → 三张模式卡片状态正确 → 联网搜索总开关在「当前连接」卡片、
渠道标签页里没有第二个 → 切换总开关(提示逐层成立、有会话时弹确认框、等一个轮询周期不弹回)→
渠道配置四槽渲染正确 → 获取可用模型 → 保存 → 刷新页面确认落盘 →
深色模式 → 切换模式 → 日志表格 → 退出服务。

服务用隔离 HOME 起在临时端口验收,不碰用户真实的 `~/.csswitch`。
